# Прошивки робота: 4 × Arduino Mega 2560 / Mega Mini

Одна плата — USB/I²C мастер, три — слейвы рулевых модулей. На каждой плате
встроены управление своим TB6600 и BLDC-интерфейс; мастер также адресно
управляет модулями FR/RL/RR по I²C. D18/оптопара **не используется**.

> **Безопасность прежде сборки:** это экспериментальный прототип, не система
> аварийного останова. Не испытывайте тягу, когда колёса стоят на земле. Перед
> любым тестом тяги поднимите все колёса, проверьте уровни сигналов, ограничьте
> питание и установите независимый физический e-stop в силовую цепь BLDC.
> Не подключайте моторы напрямую к Arduino и не подавайте неизвестное напряжение
> на её выводы.

## Состав и адреса

| Плата | Файл | Назначение | I²C-адрес |
|---|---|---|---:|
| 1 | `motor_master/motor_master.ino` | мастер + FL | не применимо |
| 2 | `motor_node/motor_node.ino` | FR | 2 |
| 3 | `motor_node/motor_node.ino` | RL | 3 |
| 4 | `motor_node/motor_node.ino` | RR | 4 |

В начале `motor_node.ino` перед загрузкой задайте пару параметров:

```cpp
#define NODE_ADDRESS 2
#define MODULE_ID "FR"
```

Для следующей платы поменяйте их на `3` / `"RL"`, затем `4` / `"RR"`.
Выберите в Arduino IDE плату **Arduino Mega or Mega 2560** и правильный порт.
У Mega Mini на ATmega2560 используется тот же профиль. Загрузите мастерскую
прошивку только на плату FL, а вариант узла — на три оставшиеся платы.

## Распиновка — на каждой из четырёх плат

| Arduino | Сигнал | Назначение |
|---|---|---|
| D2 | BLDC SC | тахометр, вход `INPUT_PULLUP` |
| D3 | BLDC speed | PWM выхода контроллера скорости; команда ограничена 0–20% |
| D4 | BLDC DIR | направление тяги |
| D5 | BLDC BRAKE | тормоз; включён при старте и после STOP/watchdog |
| D6 | TB6600 PUL+ | импульсы шагов рулевого мотора |
| D7 | TB6600 DIR+ | направление рулевого мотора |
| D8 | TB6600 ENA+ | разрешение TB6600; по умолчанию отключён |
| D18 | — | не подключать; оптопара не используется |
| D20 / SDA | SDA | общая I²C-шина всех четырёх плат |
| D21 / SCL | SCL | общая I²C-шина всех четырёх плат |
| GND | общий GND | общий сигнальный ноль контроллеров и плат |

Сверьте именно с документацией ваших BLDC-контроллеров и TB6600: назначение,
активный уровень, ток входа и полярность могут отличаться от этого прототипа.
Если входы драйвера требуют большего тока/другого уровня, примените рассчитанный
драйверный каскад. У всех Arduino должны быть общие SDA/SCL/GND, уникальные
адреса и совместимые уровни логики; не соединяйте 5-вольтовую I²C-шину напрямую
с 3,3-вольтовой электроникой без преобразователя уровней. При необходимости
используйте подходящие подтяжки и короткую шину.

В обоих `.ino` полярности задаются константами `BLDC_BRAKE_ACTIVE_LEVEL`,
`BLDC_DIR_FORWARD_LEVEL`, `STEPPER_ENABLE_ACTIVE_LEVEL` и
`STEP_DIR_POSITIVE_LEVEL`. Значения по умолчанию не заменяют проверку на
конкретных контроллерах. На старте PWM равен нулю и тормоз включён.

### Важно о PWM на D3

`analogWrite()` выдаёт **цифровой PWM**, а не постоянное аналоговое напряжение.
Команда `d 20` задаёт примерно 20% duty cycle на D3 (с ограничением в прошивке),
а не гарантированную скорость или напряжение на моторе. Если ваш регулятор
ожидает аналоговый вход 0–5 В, нужен подходящий RC-фильтр с буфером или ЦАП;
рассчитайте частоту и диапазон по документации регулятора. Подключать D3
напрямую можно только если вход контроллера явно допускает PWM 5 В. Параметр
`TACH_PULSES_PER_REV` настройте под таховыход SC.

## Программный ноль рулевого модуля

Без оптодатчика абсолютный угол после запуска неизвестен. Прошивка не ставит
`cal=1` автоматически и отклоняет команду угла до ручного обнуления. Для каждого
колеса отдельно физически выставьте его прямо, затем нажмите в интерфейсе
**«Задать 0°»**. Команда только обнуляет счётчик шагов, мотор не движет.
После перезапуска соответствующей Arduino ручной ноль теряется и его задают
снова. Допустимый угол — ±32° относительно нуля.

`STEPS_PER_DEGREE` по умолчанию унаследован от прототипа (133.333) и должен быть
проверен на собранном рулевом узле:

```text
шагов/градус = полные_шаги_двигателя × микрошаг_TB6600 × передаточное_отношение / 360
```

Непроверенное значение может привести к неверному показанию угла и механическому
упору. Первые проверки рулевого привода также выполняйте без нагрузки и на
минимально безопасном токе/скорости.

## Управление тягой и блокировки

Пульт отправляет по USB Serial команды мастеру (115200 бод):

```text
w FL zero      # ручной ноль FL, физически выставленного прямо
w RR -5.0      # повернуть один модуль к -5°
d 8            # удерживаемая тяга вперёд, 8%
d -8           # удерживаемая тяга назад, 8%
b              # PWM 0, тормоз включён на всех четырёх платах
```

Сервер и прошивка ограничивают тягу ±20%. Веб-интерфейс посылает heartbeat
каждые 200 мс, пока зажата кнопка. Master и каждый узел имеют локальный watchdog:
если команда не пришла в течение 650 мс, плата ставит PWM в ноль и включает
тормоз. При направлении тяги ненулевое движение разрешено только если мастер
видит свежие ответы всех трёх слейвов, все четыре ручных нуля заданы, рулевые
моторы неподвижны и углы выровнены в пределах 2,5°. Рулевой шаговый привод
блокируется на время активной тяги. STOP вытесняет ожидающие команды из очереди
USB-сервера.

Это лишь программные interlock-и. Они не обнаруживают препятствия, обрыв
силовой цепи, механическую неисправность, отказ контроллера или зависание всей
платы; не полагайтесь на веб-кнопку как на e-stop.

## Протокол и телеметрия

Мастер передаёт Linux строки вида:

```text
@TLM mod=FL deg=0.00 tgt=0.00 moving=0 cal=1 cycle=0 calib=0 opto=0 rpm=0.0 drive=0 t=12345
```

`cal=1` означает только установленный вручную программный ноль. `rpm` — расчёт
по D2/SC. `drive` — последний процент, сообщённый локальной платой модуля.
Узел возвращает мастеру I²C кадр CSV: текущие/целевые шаги, `moving`, `zeroSet`,
`rpm_x10` и `drivePercent`. Мастер проверяет ответ каждого адреса и публикует
кадр на каждый модуль. Старый формат без поля тяги не считается совместимым с
текущей версией firmware interlock-а.

Для ручной проверки используйте Serial Monitor на **115200 бод** с окончанием
строки Newline. Закройте Serial Monitor перед запуском Flask: один UART не может
одновременно использоваться двумя процессами. Сначала проверяйте телеметрию и
логику нуля, затем руление без тяги. Любой тест тяги — только с вывешенными
колёсами, физическим e-stop, малым значением (например 1–5%) и кратким нажатием.
