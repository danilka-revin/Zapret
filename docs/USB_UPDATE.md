# Обновление программы BULKA из файла

Подписанный **`robot-update.zip`** можно взять из **Assets** релиза **BULKA USB**
в [GitHub Releases](https://github.com/danilka-revin/Zapret/releases), когда
администратор его опубликует. Один и тот же файл можно передать с другого ПК
через веб-пульт или положить на флешку. Роботу не нужен доступ к интернету.
Старый формат `robot-update.bulka` тоже работает. **`Code → Download ZIP`
и `Source code (zip)` не подходят:** это архивы исходников без подписи пакета
и истории Git.

## Один раз: подготовить робота

1. Установите и запустите версию программы с поддержкой загрузки ZIP.
   Если обновление доступно пока только по сети, сделайте это один раз кнопкой
   «Обновить с GitHub». Если на роботе уже есть прежний USB-режим для `.bulka`,
   можно распаковать официальный ZIP **на ПК** и для первой установки передать
   с флешки внутренний `robot-update.bulka`.
2. Пульт должен работать в Git-клоне проекта на той же ветке, что и пакет
   (для релиза — `main`). На роботе нужны Git и `ssh-keygen -Y verify`
   (из пакета `openssh-client`); для флешки также нужен `findmnt`.
3. Получите публичный ключ выпуска `bulka-usb-update.pub` из доверенного
   источника: официального релиза репозитория или у администратора. Сверьте
   отпечаток с администратором при первом добавлении, а не доверяйте ключу,
   найденному рядом с файлом на флешке. В каталоге проекта на роботе:

   ```bash
   mkdir -p data
   printf 'bulka-update %s\n' "$(cat /путь/к/bulka-usb-update.pub)" >> data/usb-update-signers
   ```

   Этот локальный файл должен читаться пользователем веб-пульта и не быть
   доступным посторонним на запись. Свой ранее добавленный ключ можно оставить:
   допустимы несколько доверенных ключей. Закрытый ключ на робота не переносится.

## Загрузка с другого ПК, без флешки

1. Подключите ПК к той же сети, что и робот, или к Wi-Fi самого робота.
   Откройте `http://IP-РОБОТА:8080/` и войдите как оператор.
2. Откройте **«Обновить с GitHub» → «Загрузить с ПК»**. Выберите скачанный
   `robot-update.zip` или `robot-update.bulka` и нажмите **«Загрузить и проверить»**.
   Пульт проверит подпись и контрольную сумму, покажет версию и не начнёт
   установку сам. Лимит загрузки через браузер — **512 МиБ**; больше — с флешки.
3. Остановите робота и включите **E-STOP**. Если включили его уже после загрузки,
   нажмите **«Проверить»**, не загружая файл повторно. Сверьте версию и нажмите
   **«Установить обновление»**. Оставьте E-STOP включённым до возвращения связи
   с пультом. Платы Arduino обновление не прошивает.

На роботе хранится один проверенный загруженный пакет: новая успешная загрузка
заменяет его, а после успешной установки файл удаляется. Неполная или
неподписанная загрузка не меняет рабочую версию и не заменяет принятый пакет.

## Установка с флешки

Скопируйте один `robot-update.zip` или `robot-update.bulka` **в корень флешки**.
Другие файлы можно оставить. Безопасно извлеките флешку из ПК после записи.
Остановите робота, включите E-STOP, подключите флешку. В пульте откройте
**«Обновить с GitHub» → «С флешки (без интернета)»**, проверьте версию и нажмите
**«Установить обновление»**. Не извлекайте флешку до окончания.

Для автоустановки с флешки можно добавить `RC_USB_UPDATE_AUTO=1` в `.env` и
перезапустить пульт. По умолчанию она выключена; даже в этом режиме обновление
не начнётся без E-STOP или доверенной подписи. На загрузку с ПК настройка не
влияет: там установка всегда подтверждается оператором.

Ubuntu должна смонтировать флешку. Обычно это происходит в сеансе рабочего
стола (`/media/...` или `/run/media/...`). Без него настройте монтирование,
например под `/mnt/bulka-update` с `ro,nosuid,nodev,noexec`, и задайте
`RC_USB_UPDATE_MOUNT=/mnt/bulka-update` в `.env`. Пользователю пульта нужен
доступ на чтение флешки. Сам пульт не монтирует устройства и не требует `sudo`.

## Администратору: собрать и опубликовать ZIP

На ПК с интернетом, Git, Python 3.9+ и OpenSSH создайте отдельный ключ подписи
(не ключ для входа по SSH). Закрытый ключ храните у себя: не кладите его на
флешку, не добавляйте в Git и не передавайте в чат. Роботу нужен только публичный
`.pub`, который добавляется один раз по инструкции выше.

В обычном Git-клоне проекта (не `--depth 1`):

```bash
ssh-keygen -t ed25519 -f ~/.ssh/bulka-usb-update -C bulka-usb-update  # один раз
mkdir -p ~/bulka-release
python3 scripts/make_usb_update.py ~/bulka-release --key ~/.ssh/bulka-usb-update --zip
```

Скрипт упакует коммит из `main` на GitHub, а не локальные изменения, и выведет
полный хеш версии. Для публикации создайте релиз **BULKA USB** с тегом на этом
коммите и прикрепите `robot-update.zip` и публичный `bulka-usb-update.pub` в
**Assets**. Ссылку отправьте оператору; ему ничего собирать или подписывать не
нужно. Если ZIP больше 512 МиБ, используйте флешку или соберите меньший пакет.

Без `--zip` скрипт создаёт `robot-update.bulka`. Для выбора коммита в истории
ветки используйте `--revision ПОЛНЫЙ_ХЕШ`; для другой ветки — `--branch`;
для меньшего пакета — `--base` с полным хешем `git rev-parse HEAD` на роботе.
Если не хватает базовых коммитов, сделайте полный пакет без `--base`.

## Проверки и журнал

- Пульт не извлекает и не запускает посторонние файлы из ZIP. Он читает ровно
  один подписанный пакет из архива и только после проверки передаёт Git-bundle
  локальному Git. Разошедшаяся ветка, локальные правки и отсутствие E-STOP
  блокируют установку. Старые версии повторно не устанавливаются.
- `.env`, настройки и карты в `data/` сохраняются. Зависимости берутся из
  `vendor/`. При ошибке проверки кода или установки зависимостей исходники
  откатываются; драйверы ROS 2 автоматически офлайн не пересобираются.
- Ход установки виден в пульте, результат — в `var/update-state.json`. Если
  автоустановка с флешки пропущена до запуска, причина в журнале веб-пульта.
