# Основа обучения YOLO: p25543770-lang/yolo-stop

Требование использовать [этот репозиторий](https://github.com/p25543770-lang/yolo-stop)
выполнено **как источник фотографий и видео для обучения**, а не только как
ссылка в документации. Закреплён commit
[`3cb277bfadf7d0034943117f9146d4b92bb773a9`](https://github.com/p25543770-lang/yolo-stop/commit/3cb277bfadf7d0034943117f9146d4b92bb773a9).
Данные не подменяются меняющейся веткой `main`.

## Что взято и что добавлено здесь

В закреплённой ревизии: **415 JPEG, 8 MP4, вложенный ZIP со старыми фото**.
Готовой YOLO-разметки, обучающего Python-кода и checkpoint в ней нет.
Поэтому основа — именно её медиаматериалы; сборщик, группировка, агентские
исправления и обучение Ultralytics YOLOv8n находятся в текущем проекте.
COCO-инициализация получена отдельно: её происхождение и оговорки описаны
в [VISION_TRAINING.md](VISION_TRAINING.md), а не приписаны исходному репозиторию.
Код из скачанного репозитория не исполняется.

После удаления точных копий канонический датасет содержит **308 фото + 65
видеокадров = 373 изображения**, 260 TRAIN / 61 VAL / 52 TEST.
Кадры одного видео и близкие изображения сохраняют одну группу/часть.
Предметная область не расширялась: STOP, **знаки** перехода/неровности,
светофор с цветами, отдельные конусы/столбики. Разметка агентская и местами
эвристическая, **не независимая человеческая ground truth**.

## Загрузка/восстановление без повторной разметки

После установки [закреплённого окружения](VISION.md#обучение), из корня проекта:

```bash
# Загружает закреплённый ZIP в .cache/vision/source/ при отсутствии кеша.
# Восстанавливает только отсутствующие изображения и исходные MP4.
.venv/bin/python scripts/restore_vision_source.py --restore-missing

# Проверка из имеющегося архива: без сети и без записи медиаматериалов.
.venv/bin/python scripts/restore_vision_source.py \
  --zip .cache/vision/source/source-repo.zip --no-download
```

Можно передать другой путь `--zip`, но **только к одному из двух известных
архивов той же закреплённой ревизии**, а не произвольный источник.

Скрипт:

- проверяет SHA-256 архива, URL/revision в сохранённом `dataset.json`,
  полный список и SHA всех 8 видео;
- читает фото в том числе из вложенного ZIP; восстанавливает видео-JPEG
  **на сохранённых номерах кадров, JPEG quality=92**, проверяя каждый SHA;
- сверяет все 373 изображения с `samples.json`, не запускает авторазметку,
  pHash-группировку, переразбиение, обучение или подбор порога;
- **не перезаписывает** существующие конфликтующие пиксели; ошибки SHA,
  чужая ревизия, выход пути/симлинки или утечка видео между частями — отказ;
- не меняет `.txt`-метки, review, `data.yaml`, группы или split. Сначала
  проверяет все исходные медиа и конфликты, затем создаёт отсутствующие файлы;
- кладёт MP4 в `.cache/vision/video-review/`, где их ожидают существующие
  рецепты дообучения и просмотра. JPEG/ZIP/MP4 остаются вне Git.

Контрольные суммы архивов:

| Архив | SHA-256 |
| --- | --- |
| ZIP по закреплённому commit, используемый для восстановления | `464f43a9042be1e802745b7f00c8c44074b51d5bea8c4611eb4553afa5f55c70` |
| Исторический ZIP по main-ref той же ревизии, записанный при обучении | `762d6fa93f6f5b8103041cfced32de30b32d752399a37742e7f05d30499a0b88` |

Разные имена корневой папки/упаковка дают разные SHA ZIP. Они не подменяются
в исторических метаданных: дополнительно проверены **сами байты каждого
использованного изображения/видеокадра и MP4**. На другой версии декодера/JPEG
при несовпадении SHA будет ошибка, а не молчаливое принятие других пикселей.
Проверенное окружение использует OpenCV headless 4.11.0.86.

`scripts/vision_dataset.py` остаётся сборщиком **нового** набора с предложением
меток/групп/разбиения. Для воспроизведения уже обученных весов нужен
`restore_vision_source.py`, а не повторная генерация этих решений.
`train_vision.py` больше не вызывает сборщик молча, когда в checkout уже
есть сохранённые метки/метаданные, но отсутствуют пиксели или часть snapshot:
он останавливается с командой восстановления. Новый набор строится лишь
при действительно отсутствующем snapshot либо явно отдельным сборщиком.
