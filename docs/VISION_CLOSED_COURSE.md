# Светофор: ожидание 5 секунд только на закрытом полигоне

Явно включаемый **рекомендательный режим для закрытого контролируемого
полигона под наблюдением оператора**. Не предназначен для дорог общего
пользования. По умолчанию выключен. Он не улучшает точность модели и не
отменяет [непройденные критерии кандидата](VISION_ROBOT_TRAINING.md).

## Правила

| Наблюдение | Результат |
| --- | --- |
| Подтверждённый свежий green | Обычный tracker публикует `state=green`, `action=go`, как раньше |
| Видимый светофор, но цвет unknown | Наблюдаем тот же корпус на свежих кадрах 5 секунд |
| 5 секунд непрерывных unknown без замеченного red/yellow | Отдельная **рекомендация** `proceed_closed_course`; цвет остаётся unknown, `action` остаётся wait |
| Red/yellow хотя бы с одной свежей камеры | Немедленная блокировка рекомендации, даже если unknown другой камеры увереннее |
| После red/yellow цвет снова unknown | Блокировка сохраняется; таймаут её не обходит |
| Потеря корпуса/камеры, ошибка JPEG, старый/повторённый кадр без новых наблюдений | Рекомендация отзывается, новое ожидание начинается заново |
| Другой корпус или камера | Новые 5 секунд, накопленное время не переносится |
| Нет связи браузера с API | Лампы/предыдущая рекомендация сбрасываются в unknown/wait |

Блокировку после red/yellow снимает только **новое подтверждённое green**
или явный полный сброс наблюдений/перезапуск vision оператором. Выключение
распознавания через обычную настройку и его повторное включение её не стирают.
E-STOP этим не снимается.

## Включение

Только после организации безопасного стенда, изолированного от людей/дороги:

```dotenv
# В .env.example сохранён 0. Включать вручную только для закрытого полигона.
RC_VISION_CLOSED_COURSE_TIMEOUT=1
```

После изменения окружения перезапустить vision/приложение штатным способом.
Через `/api/vision/config` включить этот режим нельзя. Рабочий `.env` и
production-веса при реализации не изменялись.

Сервис **не управляет моторами**, не вызывает навигационное «продолжить»,
не обходит E-STOP, лидар, препятствия и разрешения оператора. Это отдельное
поле для экрана и будущей интеграции с контроллером закрытого полигона, а не
переделка неизвестного сигнала в разрешающий зелёный. **Робот сам не поедет
только от включения этого параметра.**

## API и экран

`GET /api/vision/state` и `/api/vision/field` сохраняют обычный результат
классификатора и tracker. Дополнительное поле, пример после ожидания:

```json
{
  "trafficLight": {
    "state": "unknown",
    "action": "wait",
    "closedCourse": {
      "enabled": true,
      "mode": "closed_course_advisory",
      "phase": "timeout_advisory",
      "waitS": 5.0,
      "elapsedS": 5.0,
      "remainingS": null,
      "stopLatched": false,
      "recommendation": "proceed_closed_course",
      "controlsMotors": false
    }
  }
}
```

Панель камер показывает остаток ожидания либо подпись
«ПОЛИГОН: рекомендация проезда по таймауту (не зелёный)». Зелёная лампа от
таймаута **не включается**. В выключенном режиме `phase=disabled`,
`recommendation=none` и существующее поведение цветов не меняется.

## Как считается время и ограничения

- Пять секунд считаются **монотонными часами** между новыми наблюдениями,
  не временем опроса API, не timestamp браузера и не одним снимком + sleep.
- Нужны возрастающие capture timestamps, возраст кадра и разрыв между
  новыми наблюдениями не более `min(1 с, RC_VISION_TRAFFIC_STALE_S)`.
  Старые, будущие, повторные и переставленные кадры не продлевают разрешение.
- Один кандидат: одинаковая камера, IoU с предыдущей **и начальной** рамкой
  ≥0.3. Это грубое сопоставление, не доказательство идентичности светофора
  или отношения сигнала к выбранной полосе/маршруту.
- Это **время наблюдения**, не доказательство фактической остановки робота.
  Подлинность capture timestamps доверяется источнику кадров.
- При отключении сервиса, остановке потока, ошибке кадра или смене порога
  накопленный таймер отменяется. По истечении свежести рекомендация не
  сохраняется даже без следующего update.

Реализация: `robot_control/vision/closed_course.py`, интеграция — `service.py`.
Классификатор, выбор весов, обучающие/VAL/TEST метки и пороги кандидата не
менялись ради этого поведения. Тесты: `tests/test_vision_closed_course.py` и
`tests/js/vision_panel.js` — точная граница 5 с, дубликаты/потеря кадров,
смена корпуса/камеры, red/yellow latch, API, отключение и потеря связи UI.

## Результаты перед слиянием

- **31 новый Python-тест** этого режима; профильный набор после интеграции:
  **232 passed, 1 skipped**, Node `vision panel: OK`.
- Полный pytest после включения актуального main: **2238 passed, 30 skipped,
  1 failed**, 358.96 с. Единственное падение — прежний Kinect
  `test_depth_to_scan_wall_in_front_and_floor_filtered`. Его тест, Kinect
  и sensor-layout побайтно совпадают с main; посторонние assertions
  не менялись и не отключались. Полный набор **не объявляется полностью зелёным**.
- SHA production/всех сохранённых кандидатов/ONNX/VAL-профиля и меток
  повторно сверены; протокол выбора и показатели модели не менялись.

Логи и проверка неизменности: `models/vision/training/closed-course/checks.json`.
