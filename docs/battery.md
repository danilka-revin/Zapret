# Четвёртая страница бортового экрана: JBD BMS и все банки

На `/kiosk` нажмите **«АКБ · все банки · 4»** в верхней строке. Из панелей
руления и камер доступна кнопка **«АКБ · 4»**. PIN для просмотра не нужен.
Кнопка «Назад» или свайп вправо возвращает главную статистику. При переходе
с руления на АКБ отправляется остановка тяги; настройки BMS эта страница
не меняет.

## Откуда взят способ чтения

Реализация сверена с репозиторием
[danilka-revin/ploter_a1](https://github.com/danilka-revin/ploter_a1),
коммит `cdbb00c1e3f2a5406e60e57d917616b54d215f35`:

- `jbd-bms-py/jbd_bms/protocol.py`: формат кадров JBD, контрольная сумма,
  регистры `0x03` / `0x04`, масштабы, знаковый ток, температуры и маски балансировки;
- `jbd-bms-py/jbd_bms/client.py`: UART **9600 8N1**, без flow control,
  запросы с ожиданием ответа;
- `jbd-bms-py/jbd_bms/service.py`: фоновый опрос и переподключение.

В этом проекте реализовано только чтение. Qt, Node-сервер и зависимости
интерфейса исходного приложения не нужны; используется уже имеющийся `pyserial`.
Команды записи, заводской режим, изменение ёмкости, порогов и ключей **не перенесены**.

## Подключение на роботе

1. Подключите диагностический UART **совместимой JBD BMS** через подходящий
   USB–UART адаптер. Распиновку, уровни сигналов и необходимость гальванической
   развязки проверьте по документации своей платы. Не подключайте напряжение
   силовых выводов аккумулятора к UART или USB.
2. Найдите постоянный путь адаптера:

   ```bash
   ls -l /dev/serial/by-id/
   ```

3. Укажите **один конкретный порт**, не glob и не список, в `.env` проекта:

   ```dotenv
   RC_BMS_PORT=/dev/serial/by-id/usb-ВАШ_АДАПТЕР_BMS
   ```

   Пустое значение отключает опрос. Не указывайте порт Arduino/лидара и не
   запускайте одновременно стороннее приложение `ploter_a1` на том же порту.
   На Linux пользователь процесса должен иметь доступ к порту (группа `dialout`).
   Имя `ttyUSBx` допустимо, но может поменяться после перезагрузки.
4. Перезапустите **обе** службы, чтобы шасси и лидар тоже прочитали резервирование
   порта из `.env`:

   ```bash
   sudo systemctl restart robot-control robot-kiosk
   ```

   При ручном запуске перезапустите пульт и `./scripts/kiosk.sh`. Ошибки подключения:

   ```bash
   journalctl -u robot-kiosk -f
   ```

Читает UART только бортовой сервер (`RC_KIOSK_PORT`, по умолчанию **8090**).
Пульт на 8080 получает эти данные по локальному HTTP, не открывая порт второй раз.
Поэтому для страницы АКБ на `8080/kiosk` тоже должен работать бортовой сервер.
Порт BMS исключается из поиска лидара и шасси с учётом symlink/realpath; при
совпадении с `RC_SLAM_PORT` мастер не запускается и пишет ошибку в журнал.
Дополнительно применяется общий межпроцессный замок UART.

## Что видно на странице

- заряд, напряжение, знаковый ток (**плюс — заряд, минус — разряд**) и мощность;
- остаточная / полная ёмкость в Ач, циклы;
- все температуры датчиков BMS, состояния ключей заряда/разряда, активные защиты;
- число ожидаемых и реально полученных банок;
- минимум, максимум, среднее и разброс напряжений;
- **каждая банка** отдельной строкой: номер, В и мВ, отклонение от среднего,
  флаг балансировки и отметки минимума/максимума. Список прокручивается, не
  ограничен четырьмя, двенадцатью или шестнадцатью строками; проверен также на 32 банках.

Число банок берётся из ответа самой BMS, а не из конфигурации батареи в
`slam_gui/backend.py`. Для исходной батареи **12S 3P** это 12 последовательных
групп: JBD не измеряет отдельно три параллельных элемента внутри группы.
Нельзя получить 36 независимых напряжений или температуру каждой банки, если
сама плата их не передаёт. В интерфейсе эти данные не выдумываются.

Когда BMS настроена, сводка АКБ на главном **бортовом** экране тоже берёт заряд,
напряжение, ток, мощность и максимальную температуру из JBD. Запас хода не
вычисляется этим протоколом и отображается прочерком. Без `RC_BMS_PORT` главная
сводка продолжает работать от прежнего источника шасси, но четвёртая страница
не подставляет его данные вместо реальных банок.

## Полнота, связь и отчёт

Опрос регистров `0x03` и `0x04` выполняется в фоне раз в секунду. HTTP не ждёт
UART. Ответы проверяются по длине, завершающему байту, контрольной сумме,
регистру и статусу. Таймаут запроса — 0,8 с; после ошибки соединение закрывается
и повторно открывается через 3 с. При ошибке либо возрасте измерения более
5 с показания помечаются как неактуальные. Демо-напряжений банок нет.

Если BMS объявила, например, 16 банок, но прислала 15, страница показывает
**«Неполный отчёт»** и отдельную строку №16 **«НЕТ ДАННЫХ»**. Если прислала
больше объявленного, лишние строки тоже сохраняются с предупреждением.
Минимум/среднее/разброс в таком случае относятся только к полученным значениям,
а не ко всей батарее. Отсутствующие показания не превращаются в нулевые вольты.

**«Скачать CSV»** выгружает текущий серверный снимок: время, общие параметры,
защиты, температуры и строки **всех** банок. Неполнота явно записана в CSV,
включая строки отсутствующих банок. При потере связи/устаревших данных выгрузка
запрещена (`503`), чтобы не выдать старый отчёт за свежий. Формат: UTF-8 с BOM,
разделитель `;`, имя `battery-report.csv`. Это снимок на момент выгрузки, а не
накопительная история и не заключение о здоровье элементов. Разные химии имеют
разные допустимые напряжения; универсальные «исправна/неисправна» не вычисляются.

Публичные API обоих серверов:

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/battery` | Статус связи, полнота, возраст и последний снимок всех банок |
| `GET /api/battery/report.csv` | Свежий CSV; при отсутствии свежих измерений `503` |

Телеметрия публична, как и остальные данные киоска. POST/управления BMS нет.

## Проверка без оборудования

```bash
.venv/bin/python -m pytest -q tests/test_battery.py
```

Проверяются кадры, фрагментация, CRC/checksum, знаковый ток, температуры,
балансировка 32-й банки, отсутствие/избыток банок, свежесть, CSV, резервирование
UART, HTTP и JS-отрисовка. На POSIX дополнительно запускается настоящий
`pyserial` через PTY с эмуляцией ответов JBD. Реальная плата в среде разработки
не подключена: реальные показания и совместимость конкретной модели нужно
проверить на роботе.
