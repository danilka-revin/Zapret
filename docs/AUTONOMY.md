# Автономное движение и построение карты (4 × C930e + Kinect 360 + лидар)

Робот сам объезжает помещение и достраивает карту: ищет границу неизведанного,
строит безопасный маршрут по существующему планировщику, едет, обновляет
occupancy grid, сохраняет карту и повторяет. Это **не Nav2 и не сертифицированная
система безопасности** — это осторожный режим поверх уже существующей
навигации `robot_control/navigation.py`.

## Что откуда берётся

| Сенсор | Роль | Куда идёт |
|---|---|---|
| **Лидар 360°** (RPLIDAR/LD06/LDS-01/ROS 2) | основной источник карты и позы | `SlamMapService.ingest()` + scan matching, `NavigationService._preflight` |
| **Kinect 360** (спереди по центру) | глубина, ближняя зона и препятствия впереди | `POST /api/kinect/depth` → `kinect.depth_to_scan()` → `SlamMapService.ingest_kinect()` в **ту же** сетку |
| **4 × Logitech C930e** (FL, FR спереди; RL, RR сзади по бокам) | круговой обзор и визуальные ориентиры | MJPEG `/api/camera/<0…3>/frame`, кадры с привязкой к позе в `data/landmarks/` |
| Одометрия/телеметрия колёс | подтверждение готовности тяги и停下 | существующий `MasterBridge`/`NavigationService` |

Kinect **не** участвует в оценке позы и не подменяет «свежесть» лидара: позу
по-прежнему определяет 360° скан. Поэтому неоткалиброванный Kinect не может
«сдвинуть» локализацию, а навигация не поедет, если лидар пропал.

## 1. Физическое подключение

* 4 камеры C930e — в четыре USB-порта с отдельным питанием (хаб с внешним
  питанием обязателен: 4 камеры + 4 Arduino + лидар + Kinect).
* Kinect 360 — отдельный USB (и его собственный блок питания!): у Kinect v1
  глубина работает через `libfreenect`, `OpenNI2` или ROS 2.
* Лидар 360° как обычно, см. [connections.md](connections.md) и
  [ROS2_LIDAR.md](ROS2_LIDAR.md).

Порты камер закрепите стабильными путями `/dev/v4l/by-id/…` — иначе после
перезагрузки `video0…video3` перепутаются. Назначить порты можно на бортовом
экране: свайп «Камеры» → «Настройка камер» (без PIN), либо прямо в `.env`:

```ini
RC_CAMERA_FRONT=/dev/v4l/by-id/…FL…-video-index0
RC_CAMERA_REAR=/dev/v4l/by-id/…RL…-video-index0
RC_CAMERA_FRONT_RIGHT=/dev/v4l/by-id/…FR…-video-index0
RC_CAMERA_REAR_RIGHT=/dev/v4l/by-id/…RR…-video-index0
```

## 2. Геометрия: что нужно замерить

Ось **X — вперёд**, **Y — влево**, начало координат — центр корпуса (как на
карте лидара). `yaw=0` — камера смотрит вперёд, `+90°` — влево, `180°` — назад.
По вашим эскизам передняя пара сходится под ~50°, задняя под ~90°. Шаблон в
`.env.example` повторяет это грубо, но **обязательно замерьте** и впишите:

```ini
RC_CAMERA_FL_X_M=0.30
RC_CAMERA_FL_Y_M=0.25
RC_CAMERA_FL_Z_M=0.28
RC_CAMERA_FL_YAW_DEG=-25
... остальные три камеры ...
RC_KINECT_X_M=0.35
RC_KINECT_Y_M=0.0
RC_KINECT_Z_M=0.30
RC_KINECT_YAW_DEG=0
RC_KINECT_PITCH_DEG=0
```

Пока переменные не заданы, `GET /api/sensors/layout` возвращает
`calibrated: false`; карта при этом всё ещё строится лидаром, но не стоит
рассчитывать на точные углы обзора. C930e по умолчанию: 82° по горизонтали,
52° по вертикали; Kinect 360: 57° × 43°, 0,45…4 м.

Проверить геометрию и отсутствие дублей портов:

```bash
curl http://127.0.0.1:8090/api/sensors/layout | python3 -m json.tool
curl http://127.0.0.1:8090/api/cameras | python3 -m json.tool
```

## 3. Запуск Kinect

На борту, вместе с киоском (8090), поднимите публикатор глубины. Он не требует
изменений в приложении и не открывает USB из Flask-процесса:

```bash
# сначала без железа: один синтетический кадр, проверка всей цепочки
.venv/bin/python scripts/kinect_depth_publisher.py --source demo --once

# реальный Kinect 360 через libfreenect
.venv/bin/python scripts/kinect_depth_publisher.py --source freenect

# или OpenNI2 / ROS 2 (sensor_msgs/Image, 16UC1 мм или 32FC1 м)
.venv/bin/python scripts/kinect_depth_publisher.py --source openni
.venv/bin/python scripts/kinect_depth_publisher.py --source ros2 --topic /camera/depth/image_rect_raw
```

Публикатор уменьшает кадр до 160×120 и шлёт `uint16` (мм) в
`POST /api/kinect/depth` с заголовком `X-Robot-Control: kinect`. Сервер сам
переводит глубину в полярные лучи, отбрасывает пол/потолок
(`RC_KINECT_MIN_HEIGHT_M`…`MAX_HEIGHT_M`) и вписывает их в карту.

Проверка:

```bash
curl http://127.0.0.1:8090/api/kinect/status   # connected, frames, points
curl http://127.0.0.1:8090/api/kiosk_map       # kinectScans, kinectPoints
```

Если нужен автозапуск — добавьте публикатор в `scripts/autostart.sh` рядом с
киоском или отдельный systemd-юнит по образцу `scripts/robot-kiosk.service`.

## 4. Включение автообследования

```ini
RC_NAV_ENABLE=1          # существующая осторожная навигация
RC_EXPLORE_ENABLE=1      # сам цикл обследования
```

Затем на странице **«Карта лидара»** (или **«Движение по маршруту»**) в панели
**«Автообследование»**:

1. Убедитесь, что лидар и Kinect дают свежие данные (индикаторы в панели).
2. Осмотрите ближнюю зону вокруг робота и поставьте галочку подтверждения —
   это аналог проверки слепой зоны лидара у обычного маршрута.
3. Нажмите **«Начать обследование»**. Дальше робот едет сам: выбирает границу
   UNKNOWN-области, строит маршрут, едет, сохраняет PGM/PNG/ YAML карту и
   снимает кадры с четырёх камер.
4. **«Стоп»** или **E-STOP** мгновенно снимает тягу и завершает цикл.

То же через API (борт, 8090):

```bash
curl -H 'X-Robot-Control: exploration' -H 'Content-Type: application/json' \
  -d '{"blindZoneChecked":true}' http://127.0.0.1:8090/api/exploration/start
curl http://127.0.0.1:8090/api/exploration/status
curl -H 'X-Robot-Control: exploration' -X POST http://127.0.0.1:8090/api/exploration/stop
```

На пульте 8080 те же маршруты доступны после входа оператора и требуют
CSRF-токен (берётся из `/api/exploration/status`), команды проксируются на борт.

## 5. Ограничения и безопасность

* **Выключено по умолчанию.** Нужны `RC_NAV_ENABLE=1` и `RC_EXPLORE_ENABLE=1`,
  свежий скан лидара, качество scan matching, готовность тяги и отсутствие
  E-STOP. Любая потеря Kinect во время движения останавливает обследование.
* Цикл завершается по: пределу шагов (`RC_EXPLORE_MAX_STEPS`), времени,
  отсутствию новых границ, многократному отсутствию прироста карты, E-STOP,
  кнопке «Стоп», ошибке планировщика или таймауту поездки.
* Шасси **не умеет разворот на месте**: доступны прямые/крабовые отрезки
  в пределах ±28°, поэтому кластеры границ позади робота имеют низкий приоритет.
* Скорость — как у обычной навигации (`RC_NAV_SPEED_MPS`, по умолчанию 0,05 м/с),
  предел тяги `RC_NAV_MAX_PERCENT`. Все проверки `_preflight`, watchdog 650 мс,
  `X-Robot-Control`, CSRF и общая защёлка E-STOP сохранены.
* Ближняя слепая зона лидара (радиус `min_range` карты) остаётся единственным
  местом, где требуется человек: Kinect смотрит вперёд, сзади его нет, поэтому
  оператор подтверждает осмотр перед пуском. Не снимайте эту галочку
  (`RC_EXPLORE_REQUIRE_BLIND_CHECK=0`) без дополнительных датчиков сзади.
* **Не публикуйте 8080/8090 в интернет.** Держите доступным физический
  аварийный выключатель, первые прогоны — на вывешенных колёсах.
* Kinect v1 не видит солнечный свет, чёрные/глянцевые поверхности и стекло;
  лидар остаётся основным датчиком. Низкие препятствия (< `MIN_HEIGHT_M`) и
  объекты вне 57° спереди глубиной не увидятся — для них работают лидар и
  камеры оператора.

## 6. Визуальные ориентиры

На каждом шаге (отъезд и прибытие) `LandmarkRecorder` сохраняет по свежему
кадру с каждой из четырёх камер в `data/landmarks/` (каталог в `.gitignore`)
и дописывает `index.json` с позой, целью и ролью камеры. Посмотреть:

```bash
curl 'http://127.0.0.1:8090/api/exploration/landmarks?limit=5'
# кадры: /api/exploration/landmark/step003-cam2.jpg
curl -H 'X-Robot-Control: exploration' -X POST \
  http://127.0.0.1:8090/api/exploration/landmarks/clear
```

Это **привязанные к позе снимки**, а не визуальный SLAM: полноценный RTAB-Map /
ORB-SLAM3 требует калибровки каждой камеры, ROS 2 и отдельного стека. Карта
здесь строится лидаром + глубиной Kinect.

## 7. Диагностика

| Признак | Что проверить |
|---|---|
| «Автообследование выключено» | `RC_EXPLORE_ENABLE=1`, перезапуск процессов |
| «Сначала включите навигацию» | `RC_NAV_ENABLE=1` и готовность `GET /api/navigation/status` |
| «Нет свежего кадра Kinect» | публикатор запущен, `/api/kinect/status`, USB-питание Kinect |
| «Новых границ нет» | карта уже построена или сетка не обновляется; `/api/kiosk_map` → `scans`, `quality` |
| «Карта перестала расти» | лидар/поза стоят на месте; проверьте `matched`, `quality`, `RC_NAV_QUALITY_MIN` |
| Камеры перепутаны | закрепите `/dev/v4l/by-id/…` в «Настройке камер» |
| `duplicatePorts` в `/api/sensors/layout` | два разных `RC_CAMERA_*` указывают на один порт |
| «Поездка превысила таймаут» | `RC_EXPLORE_STEP_TIMEOUT_S`, связь с шасси, застрявшее колесо |
