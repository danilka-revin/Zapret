# Автономный заезд на закрытой трассе

Вкладка **«Автономность»** — `/autonomy` на бортовом экране (8090). Веб-пульт
(8080) проксирует её на борт; только бортовой процесс управляет шасси. После
команды **«Запустить автономность»** робот выполняет заезд сам. При загрузке
компьютера, открытии вкладки или возврате датчика после аварийного завершения
тяга сама не включается. Реальная тяга по умолчанию отключена (`RC_TRACK_ENABLE=0`).

## Что происходит на трассе

| Ситуация | Решение |
| --- | --- |
| Оранжевые столбики | Каждый столбик — препятствие, в том числе одиночный. Подтверждённая пара может обозначать проезд. Робот проверяет обе границы и габарит корпуса с запасом по намеченному направлению. Узкий, перекрытый, недостижимый или плохо видимый проезд не разрешает тягу. |
| Неожиданное препятствие | Свежий физический скан лидара отдельно проверяет путь торможения по вектору крабового хода. Препятствие или потеря полного скана завершает заезд остановкой. Объезда за пределами подтверждённого проезда нет. |
| Знак «СТОП» | Робот замедляется на подходе и тормозит до расчётного створа. Отсчёт начинается только после свежего подтверждения **именно этой команды STOP** и отсутствия вращения на всех четырёх колёсах. После полной остановки ждём 3 с (минимум), затем продолжаем, если остальные проверки позволяют. |
| Светофор | На красный, жёлтый, конфликт цветов и неясный сигнал — остановка. Разрешение дают два разных свежих кадра зелёного с одной камеры, относящиеся к тому же светофору. Старый зелёный, пропавший сигнал и рекомендация `closedCourse` не разрешают тягу. Новый красный снова тормозит, даже если зелёный уже разрешал движение. |
| Кочка | Знак предупреждает о замедлении; навигационный кадр Kinect и свежий наклон подтверждают переезд. Один кадр не считается несколько раз. Тяга добавляется порциями только при отсутствии движения на подтверждённом подъёме, не выше потолка. После расчётного выхода за дальний край неровности робот ещё немного едет медленно. Неподтверждённая, слишком высокая неровность, яма на пути или тайм-аут переезда — не успех, а остановка. |

Шасси едет **крабом**, не разворачивает корпус на месте. Перед перекладкой руля
ждёт подтверждения STOP; тягу после перекладки подаёт только когда телеметрия
показывает нужный угол всех колёс. Связь, SC, команда тяги, превышение скорости
и отсутствие прогресса проверяются в движении. Ручная команда, кнопка «Стоп»
или E-STOP снимает управление с режима. Навигация по карте и «Скан» не могут
одновременно захватить привод.

### Как расставить столбики и знаки

- Расставьте хорошо видимые столбики **по двум краям**. Пара на одной продольной
  позиции либо с небольшим смещением может обозначать створ. Если есть только
  один ряд или случайные отметки без пары, программа не дорисовывает второй
  край. Ставьте следующие пары так, чтобы они уже были видны при выходе из
  текущего створа: проезда вслепую в зоне прямо у камер нет.
- «Ширина / минимум» во вкладке — оценка расстояния **между центрами** столбиков и
  необходимое расстояние. Минимум не меньше `ширина корпуса + 2 × (запас +
  радиус основания столбика)`. Замерьте корпус с колёсами и выступами, высоту
  и самое широкое основание столбиков. Например, для 0,60 м, запаса 0,12 м и
  радиуса 0,125 м нужно не меньше 1,09 м между центрами на прямом участке;
  на повороте может потребоваться больше. Это расчёт, не натурный допуск.
- Знак и светофор должны быть видны на подходе. Светофор должен оставаться
  различимым (в том числе в краевой камере) до наблюдения позади корпуса;
  если он пропал раньше, робот не считает проезд подтверждённым. Для первого
  прогона используйте один различимый светофор за раз. Программа оценивает
  створ по положению знака, а не распознаёт нарисованную стоп-линию.
- Для кочки нужен знак «Искусственная неровность» и различимый Kinect рельеф
  впереди. Высокий бордюр или коробка — не кочка, которую нужно продавить.

## Сначала без тяги

1. На вкладке **«Сухой прогон»** попробуйте полную трассу, широкий и узкий
   проезды. То же из консоли без робота:

   ```bash
   .venv/bin/python scripts/track_autonomy_sim.py --scenario full
   .venv/bin/python scripts/track_autonomy_sim.py --scenario gate
   .venv/bin/python scripts/track_autonomy_sim.py --scenario blocked_gate
   ```

   Сценарии дополнительно: `straight`, `stop`, `bump`, `light`. В `blocked_gate`
   успешный результат — `blocked` и **0 м**, а не проезд. Сухой прогон использует
   синтетические сенсоры и не вызывает реальные провайдеры, USB или тягу. Он
   не тестирует распознавание, динамику шасси и тормозной путь.
2. Настройте [зрение](VISION.md), назначьте камеры по физическим портам и
   измерьте [геометрию камер и Kinect](AUTONOMY.md). Для реальных кадров включите
   `RC_VISION_ENABLED=1` на борту. Обычный киоск и сухой прогон
   запускаются без NumPy/OpenCV; для разбора реальных кадров нужны зависимости
   из `requirements-vision.txt`. Новые экспериментальные веса не заменены:
   [отчёт о валидации](VISION_ROBOT_TRAINING.md).
3. Для прогона **на бортовых датчиках без тяги** установите
   `RC_TRACK_ENABLE=1` вместе с `RC_TRACK_SIMULATION=1` и перезапустите киоск.
   Убедитесь, что вкладка показывает «БЕЗ ТЯГИ», проверьте разметку, ширину и
   направление. Подведите робота к разным знакам в ручном стендовом режиме и
   убедитесь, что камеры/лидар видят их там, где они расположены.

## Что должно быть готово для ограниченного выезда

Перед переходом от симуляции к движению проверьте торможение и действие
**физического E-STOP**, сначала на вывешенных колёсах. Затем допустим короткий
заезд на малой скорости под наблюдением, на отделённой площадке без людей и
движущихся машин. Не используйте этот режим на дорогах общего пользования.

Для реальной тяги нужны `RC_TRACK_ENABLE=1` и `RC_TRACK_SIMULATION=0` на борту
после перезапуска, плюс выполненные проверки вкладки:

- корректная геометрия, разные порты камер, свежие кадры обеих передних камер
  и подтверждённый проезд;
- полный свежий скан физического лидара (serial/ROS 2 либо доверенный скан от
  второго процесса), с измеренным смещением и корректным направлением. Демо,
  API-скан и скан с большими угловыми пропусками не разрешают выезд;
- свежий полный **raw-depth** кадр Kinect (`navigation_frame()`, не preview с
  `notForNavigation` и не `points`/`ranges`); для кочки нужен ещё свежий IMU;
- владелец шасси `RC_SLAM_SOURCE=master`, четыре платы с заданным нулём,
  свежими SC и подтверждением STOP, нет активной калибровки, neutral/full-zero
  или другого режима тяги;
- оператор проверил ближнюю слепую зону, снял программную защёлку E-STOP после
  физической проверки и отметил осмотр перед нажатием «Запустить автономность».

Даже зелёный чек-лист не доказывает безопасность. Камеры могут пропустить
знак целиком; лидар видит только свою плоскость, Kinect v1 ограничен на солнце
и на сложных поверхностях. Нет гарантии обнаружения людей, стекла, низких
препятствий и перепадов пола. Это экспериментальный режим, не Nav2 и не
сертифицированная система безопасности.

## Настройки, диагностика и финиш

Полный список в [`.env.example`](../.env.example) и `TrackConfig.from_env`.
Подбирайте параметры по замерам на своём шасси, не по значениям симуляции.

| Параметр | Назначение |
| --- | --- |
| `RC_ROBOT_WIDTH_M`, `RC_ROBOT_LENGTH_M`, `RC_TRACK_CLEARANCE_M` | Фактический габарит и запас вокруг корпуса. |
| `RC_TRACK_POST_HEIGHT_M`, `RC_TRACK_POST_RADIUS_M` | Размеры оранжевых столбиков. Ошибка высоты искажает оценку расстояний по камере. |
| `RC_TRACK_STOP_CLEARANCE_M`, `RC_TRACK_LIDAR_MAX_AGE_S` | Проверяемый отрезок хода перед корпусом и допустимая свежесть скана. Измерьте полный тормозной путь с задержками датчиков и запасом. |
| `RC_TRACK_CRUISE_PERCENT`, `RC_TRACK_SLOW_PERCENT`, `RC_TRACK_CLIMB_PERCENT` | Проценты команды тяги, **не скорость**. Должны быть упорядочены: малая ≤ обычная ≤ предел на кочке. Замерьте движение под нагрузкой: слишком малая тяга может не тронуть шасси. |
| `RC_TRACK_MAX_SPEED_MPS` | Верхняя отсечка по SC, не регулятор и не измерение скорости корпуса при скольжении. |
| `RC_TRACK_BUMP_MAX_HEIGHT_M`, `RC_TRACK_BUMP_CROSS_TIMEOUT_S` | Ограничения для измеренной неровности и времени переезда. |
| `RC_TRACK_FINISH_DISTANCE_M` | `0` — нет финиша по метражу; ненулевое значение — остановка по измеренной дистанции. Не подставляйте длину на глаз. Время и `RC_TRACK_MAX_DISTANCE_M` — аварийные ограничения, а не финиш. |

`GET /api/autonomy/status` ничего не запускает: `blockers`, `warnings` и
`checks` объясняют готовность; `corridor` и `lidar` показывают состояние
проверок. `counters.stop`, `.bump`, `.traffic` считают соответственно
завершённую выдержку, подтверждённый переезд и проезд светофора. Для запуска
из API нужны `POST /api/autonomy/start`, `X-Robot-Control: autonomy` и явное
`{"blindZoneChecked": true}`. Остановка — `POST /api/autonomy/stop`, сухой
прогон — `POST /api/autonomy/simulate`. На веб-пульте дополнительно нужны
сессия оператора и CSRF-токен из статуса. Не публикуйте порты робота в интернет.
